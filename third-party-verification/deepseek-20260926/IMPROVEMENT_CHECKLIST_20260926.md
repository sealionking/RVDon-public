## 一、Golden Vectors 扩展 (P0)

> 这是本次验证发现的最重要问题。

### P0-1 补充大规模 K 维度的 golden vectors

**现状:** 仅 1 组 K=16 的确定性输入。  
**问题:** K=16 时 Kahan vs Naive 差异不到 1 ULP，无法展示 Kahan 补偿的实际价值。  
**证据:** K=1024 时 Kahan vs Naive 差异是 K=16 的 176 倍。Protenix 实际负载的
成对表示矩阵维度远超 16。  
**建议:**

```csv
# 在 kahan_golden_vectors.csv 中增加:
# Tile 3: WGMMA at K=128, M=16, N=8
# Tile 4: WGMMA at K=256, M=16, N=8
```

| 新增内容 | 参数 | 理由 |
|------|------|------|
| WGMMA K=128 | M=16, K=128, N=8 | Kahan 优势达到 8x, 明显可见 |
| WGMMA K=256 | M=16, K=256, N=8 | Kahan 优势达到 ~10x |
| PF_TMM K=128 | 同上 + 出向三角掩码 | 掩码验证覆盖中等规模 |
| FA_MMA K=128 | 同上 + 因果掩码 | 掩码验证覆盖中等规模 |

### P0-2 增加非确定性输入的 golden vectors

**现状:** 仅 1 组输入，模式为 `(i%7+1)×0.1`。  
**问题:** 单点验证无法建立统计置信度。  
**证据:** 随机分布（Uniform/Normal/LogUniform）测试显示 Kahan 行为一致。  
**建议:**

| 新增内容 | 参数 | 理由 |
|------|------|------|
| Uniform[-1,1] 随机种子 42 | M=16, K=32, N=8 | 统计多样性 |
| LogUniform 动态范围 e^10 | M=16, K=32, N=8 | 大动态范围, Kahan 收益显著 (4.6x) |

### P0-3 文档化当前 K=16 作为 smoke test 的定位

**现状:** 验证指南未说明 K=16 规模的局限性。  
**建议:** 在 `external_cross_validation_guide.md` 中加入:

```markdown
### 5.1 Smoke Test (Current Data)

The K=16 test vectors in this directory are a **smoke test** — they verify
that the basic algorithm, mask logic, and data format are correct. Due to
the small K dimension, FP32 accumulation errors have not yet accumulated
significantly, so the Kahan vs naive divergence is within 1 ULP.

For a more representative verification at Protenix-level matrix sizes,
see `kahan_golden_vectors_v2.csv` (K=128, K=256).
```

## 二、验证数据可信度 (P1)

### P1-1 提供 RTL 输出的可验证性机制

**现状:** 外部验证者必须无条件假设 CSV 中的 `rtl_output` 列确实来自 RTL 仿真。  
**问题:** 这是第三方验证的根本性信任瓶颈 — 无法排除 golden vectors 被手写
而非仿真生成的可能性。  
**建议 (选其一):**

| 方案 | 描述 | 工作量 |
|------|------|:---:|
| A. 仿真配方 | 提供 `reproduce.sh`: 指定 Vortex commit hash, configure flags, 输入矩阵, 预期输出 hash | 中 |
| B. 签名链 | 对 CSV 文件做 `sha256sum`, 在公开 issue/GitHub release 中发布 hash, 外部可比对 | 低 |
| C. CI artifact | 在 GitHub Actions 中自动生成 golden vectors, 附带 build log | 中 |

### P1-2 在验证指南中声明 golden vectors 的生成过程

**现状:** 指南只描述数据格式，未说明数据来源。  
**建议:** 在 `external_cross_validation_guide.md` 增加一节:

```markdown
### 2.3 Golden Vector Provenance

- `kahan_ref`: Computed by the DiVo team using Kahan 1965 FP32 algorithm
  (C++ float). Independently verified by external third-party (2026-09-26)
  producing bit-exact match.
- `rtl_output`: Generated by Verilator RTL simulation of Vortex TCU at
  commit <hash>, configure flags: --xlen=64 ISSUE_WIDTH=4 NUM_CORES=1.
  The corresponding simulation log is archived at <path or hash>.
```

## 三、测试覆盖维度 (P1)

### P1-1 增加边界值 golden vectors

**现状:** 当前输入全部在 [0.1, 1.0] 范围内, 无极端值覆盖。  
**建议:**

| 新增内容 | 参数 | 理由 |
|------|------|------|
| Denormal 测试 | A/B 含 `5e-39` 量级值 | 验证 denormal flush 行为 |
| 零矩阵测试 | A/B 为全零 | 边界条件 |
| 大值测试 | A/B 含 `1e18` 量级值 | 验证不溢出 |

### P1-2 声明多 CTA / 时序 / 性能维度的验证计划

**现状:** 任务书和指南都只覆盖数值精度。已知限制 P3-1（仅单 CTA）、P3-3
（FA_SOFTMAX 背压）无对外验证数据。  
**建议:** 在文档中增加:

```markdown
### Known Verification Gaps (Public)

The following areas are validated internally but not covered by this
cross-validation data:

| Area | Status | Plan |
|------|:---:|------|
| Multi-CTA correctness | Not in v1.0 (P3-1) | v1.1 |
| FA_SOFTMAX backpressure | Not in v1.0 (P3-3) | v1.1 |
| Timing closure (28nm) | Internal only | Report Q4 2026 |
| Power/area | Internal only | Report Q4 2026 |
```

这种诚实态度比"假装没有已知限制"更有利于建立信任。

```markdown
### FAQ

**Q: Why is Kahan vs naive divergence so small in the K=16 data?**
A: K=16 is a smoke test. FP32 errors accumulate with K, so to see
Kahan's benefit you should use the K=128 or K=256 extended vectors.

**Q: Can I use FP64 (double) for my reference implementation?**
A: Yes, but expect ~2.4e-7 differences vs CSV kahan_ref (computed in
FP32 / float). This is expected and not an error.

**Q: How do I verify the rtl_output column is genuine?**
A: See section 2.3 (Golden Vector Provenance) for the commit hash and
simulation recipe. You can reproduce the simulation if you have access
to the Vortex RTL (not distributed here).
```

## 六、实施建议

**最小可行改进 (P0-only, 预计 1-2 天):**

1. 跑一轮 RTL 仿真, 用 K=128/K=256 生成 golden vectors
2. 追加到 `kahan_golden_vectors.csv`
3. 在指南中标注原 K=16 为 smoke test, 指导新数据的使用

这三个改动将显著提升外部验证的说服力 — 从"K=16 看不到 Kahan 的价值"
变为"K=128 下 Kahan 提供 8x+ 改善, 清晰可见"。

**完整改进 (P0+P1+P2, 预计 3-5 天):**

在最小改进的基础上, 增加仿真配方/签名、边界值数据、验证覆盖缺口声明、
目录索引和 FAQ。这将使 RVDon-public 仓库的第三方验证能力达到相当专业
的水平。
